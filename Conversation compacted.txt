Key Technical Concepts:

Frontend: React 19, TypeScript 6, Vite 8, Tailwind 4, lucide-react, shadcn-ish utilities, eslint 10 with react-hooks 7 strict rules (set-state-in-effect, immutability, refs).
QR: qrcode-generator (render to canvas PNG), jsqr (decode), the BarcodeDetector API when available. Payload format HABITA|meetingId|ownerId|token. Pass links via #pase=<base64url JSON>.
Recommended production architecture (.NET): modular monolith with hexagonal architecture, plus a worker. Azure SQL (SSMS, RLS multi-tenant), Blob (SAS direct upload), Service Bus (not Kafka), Azure SignalR, Container Apps, Key Vault, Entra ID, App Insights, Outbox pattern. Azure OpenAI recommended over direct OpenAI because of Ley 1581 data residency.
Prototype backend: FastAPI + hexagonal (domain / application ports+services / adapters / api), SQLite (stand-in for Azure SQL), local FS (stand-in for Blob), in-process asyncio queue (stand-in for Service Bus), openai SDK (AsyncAzureOpenAI), uvicorn, pytest.
Recording: MediaRecorder with 60s independent segments (the next recorder starts before the old one stops), IndexedDB persistent upload queue, Wake Lock, beforeunload warning, interrupted-recording recovery via localStorage habita-rec-active, auto markers (agenda step change, poll closed).
Transcription per chunk (concurrency 3, 3 retries, backoff). Sections by agenda markers (chunk midpoint routing). Per-section LLM drafting (concurrency 4) with strict prompt (no inventions, [POR CONFIRMAR], [hh:mm:ss] citations). Deterministic header, quorum and votes table in render_acta.
Legal: Ley 1581 de 2012 (voice = personal data, consent), Ley 675 de 2001 (quorum by coefficients, not implemented).
Sandbox: Workshop Web only runs Python backends; the workshop-openai proxy supports the Responses API but not OpenAI-compatible audio transcription/TTS (probed). Dev server start.sh uses APP_PORT (3048) and backend APP_PORT+100 (3148).
